# CC Switch For Krill 0.0.4

## 中文

- 修正候选端点列表造成 WS 状态匹配失败的问题，统一配置身份与 JSON 键顺序。

本地测试版，暂未发布安装包；待本机试用确认后再推送合并改动与正式发布。

- 供应商旁仅显示 **WS**，隐藏 CMP 标志；保留原有上下文压缩功能。
- WS 标签沿用原版样式，仅改变文字颜色，没有悬浮提示。
- 修正 HTTP 回退后仍显示旧 WS 成功状态的问题，不再因历史成功而保持绿色。
- 正常 WS 请求发送后记录绿色，长请求每隔约 30 秒从已有返回数据刷新。
- 观察到 HTTP 请求、WS 连接失败或上游断开时变灰；重启和停止代理后清除旧 WS 状态。
- Krill 按供应商名称精确识别，不区分大小写，不再依赖固定 API 域名。
- 全新安装预置名为 krill 的供应商空白配置，需填写自己的端点和 API Key；已有配置不受影响。
- UI 定期读取本地状态；不额外发送握手、心跳、模型请求或压缩探测，不增加 token 用量。

颜色表示该供应商近期观察到的实际传输状态，不能保证每个模型或会话都使用相同协议。
没有新流量时不主动检查，证据超过 30 分钟后为灰色，表示尚无近期 WS 证据。

验证范围：Rust 静态检查、TypeScript 检查和 Windows x64 发布构建；未新增实际模型调用测试。

## English

- Fix WS evidence matching when provider lists hydrate candidate endpoints; normalize configuration identity and JSON key order.

Local test build; no installer is published. Merged changes remain local pending user acceptance.

- Show only **WS** beside providers; hide CMP while preserving native context compaction.
- Reuse the original chip style with text color only and no hover tooltip.
- Clear stale WS success on HTTP fallback instead of retaining green from earlier success.
- Record normal WS sends and refresh long-running turns from received traffic about every 30 seconds.
- Show gray on observed HTTP requests, WS connection failures or upstream closure. Clear old WS
  evidence when restarting or stopping the proxy.
- Identify Krill by an exact, case-insensitive provider name rather than fixed API domains.
- Seed a blank krill provider on fresh installs only; users supply their own endpoint and API key.
  Existing configurations are preserved.
- The UI reads local state only. No extra handshakes, heartbeats, model requests, compaction probes
  or tokens are added for status detection.

Color reflects recently observed transport for the provider, not a guarantee for every model or
session. No traffic means no active check; evidence older than 30 minutes becomes gray as unverified.

Validation: static Rust/TypeScript checks and a Windows x64 release build; no new live model tests.

# CC Switch 4.0.26-krill.1

## 中文

本分支专门支持 Krill，由 Xias2y 发布，基于上游 CC Switch v4.0.25 独立维护。

### 更新内容

- Codex 聚合模式支持官方账号与 Krill 的原生 Responses WebSocket。
- 保留 Krill 原生上下文压缩与回放，检查压缩内容的供应商和账号来源。
- HTTP 请求自动使用 zstd 压缩，WS 不可用时回退 HTTP。
- 保留现有模型选择、OAuth/API Key 隔离、用量记录、摘要兼容和路由故障转移。
- 使用本分支自己的更新地址与更新器签名密钥。

### 范围与验证

本版仅发布后端，尚未加入 WS / CMP 状态标志。Krill 使用供应商卡片中配置的单一端点，
未加入三线路自动选择。原生压缩密文不保证能跨供应商或账号使用。

此前后端验证包含 4,348 项库测试、109 项集成测试，以及官方账号和 Krill 的实际模型检查。
后续静态复查修正通过 Clippy 与格式检查，未再次进行实际模型验收。本版在本地编译为
Windows x64 安装程序。

### 致谢

感谢 **[@krill-lab/Superba](https://github.com/krill-lab/superba)** 的原生路由、上下文压缩和
传输参考实现，以及上游 CC Switch 贡献者。参考版本为
`f78d77a2849aceb8dffc1f27a83869ffceab7e90`，MIT 许可证保留在 `licenses/Superba-MIT.txt`。

## English

This Krill-focused fork is independently maintained by Xias2y and based on upstream
CC Switch v4.0.25.

### Changes

- Native Codex Responses WebSockets for official accounts and Krill in aggregation mode.
- Preserve Krill's native context compaction and replay, checking the source provider and account.
- Automatic HTTP zstd request compression and HTTP fallback when WS is unavailable.
- Keep existing model selection, OAuth/API-key isolation, usage logging, summary compatibility
  and routing failover.
- Use this fork's own updater endpoint and signing key.

### Scope and validation

This backend release does not include WS / CMP availability badges. Krill uses its configured
endpoint without automatic selection across three lines. Native compaction ciphertext is not
guaranteed to work across providers or accounts.

Earlier backend validation includes 4,348 library tests, 109 integration tests and live
official-account/Krill model checks. Subsequent static-review corrections passed Clippy and
formatting checks without another live acceptance run. Built locally for Windows x64.

The reference implementation and its revision are credited above; the MIT license is retained
in `licenses/Superba-MIT.txt`.

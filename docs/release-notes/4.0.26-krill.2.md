# CC Switch 4.0.26-krill.2

This Krill-focused fork is based on upstream CC Switch v4.0.25. It includes the
native official-account/Krill WS, context compaction and HTTP zstd backend from
4.0.26-krill.1 and adds the availability badges requested for aggregation mode.

## Changes

- Show only **WS** and **CMP** beside the existing default, official and model-count
  chips. Reuse the original CC Switch chip dimensions, outline and typography.
- Green text means recently verified availability for the provider's most recently
  used GPT model. Gray means unavailable, unverified or expired; hover for details.
- WS observes normal connections and responses. CMP uses real native compaction
  results or a small isolated check on model use, cached for 24 hours after success.
  Temporary probe failures wait at least 15 minutes and require further model use.
- Reading the UI only refreshes local evidence. The isolated CMP check can consume
  a small amount of quota; it sends no conversation history or tools.
- Keep the existing backend routing, account/key isolation and HTTP fallback.

## Scope and validation

This release is compiled locally for Windows x86_64 and uses the fork's signed
updater artifacts. These signatures are for the updater, not Windows Authenticode.
The UI implementation passed static Rust lint/format and TypeScript checks and a
renderer build. Earlier backend tests are documented in the previous release;
this release does not claim a new live official/Krill model acceptance run.
Krill still uses its configured endpoint, without Superba's three-line selection.
Native compaction ciphertext is not guaranteed portable across accounts/providers.

# CC Switch For Krill 0.1.0

## 中文

### 功能说明

1. **聚合模式支持原生 WS**：官方账号和 Krill 都可以通过 CCS 使用 WebSocket，承载流式输出和工具调用。
2. **支持 WS 预热和多轮增量续接**：转发客户端的连接预热、`previous_response_id` 等原生机制。
3. **Krill 支持原生上下文压缩**：GPT 模型的压缩请求和加密压缩结果按原生协议传递，不再统一改写成 CCS 的文本摘要。
4. **增加压缩上下文来源保护**：识别压缩内容所属的供应商和账号；切换后不兼容时明确报错，保留历史，不静默删除压缩内容。
5. **自动压缩 HTTP 请求体**：官方和 Krill 的适用请求可使用 zstd，遭上游拒绝时回退普通 JSON。这与上下文压缩是两个功能。
6. **WS 不可用时自动回退 HTTP**：不支持 WS、需要协议转换或握手失败时，进入兼容的 HTTP 通路。
7. **隔离第三方认证错误**：Krill 的 Key 失效等认证错误，不再被客户端误认为官方登录失效，从而触发官方账号刷新。
8. **显示被动 WS 状态标签**：根据正常请求的实际传输显示绿／灰；回退 HTTP 或连接中断时更新状态，不为标签额外发送探测请求或消耗 token。

### 其他调整

- 供应商卡片仅显示 WS，使用原版标签样式，无悬浮提示；CMP 不展示，原生上下文压缩功能保留。
- 修正候选端点造成 WS 成功状态匹配失败的问题，统一配置身份与 JSON 键顺序。
- Krill 按供应商名称精确识别，不区分大小写，不依赖固定 API 域名。
- 全新安装预置 Krill 空白配置，需填写自己的端点和 API Key；已有供应商和账号配置保持不变。
- 关于页、更新入口及近期更新详情统一指向本仓库的发布页。

### 状态与使用范围

WS 标签表示供应商近期观察到的实际传输，灰色也可能是尚未观察或证据过期。
它不能代表多个并行会话同时使用的协议；没有新流量时不主动检测，30 分钟没有新证据后显示灰色。
上下文压缩密文不保证可跨供应商或账号使用；未知来源的历史保留原样尝试，已知来源冲突才阻止转发。
Krill 使用当前配置端点，未加入三线路自动轮换。自动故障转移路由仍使用原有 HTTP 通路。
正常对话及实际上下文压缩仍按上游规则产生用量；只有标签观察不增加额外 token。

### 版本与验证

本次作为稳定版发布（非预发布）。应用、安装包、更新器和发布名称统一使用 **0.1.0**。安装包为 Windows x64 EXE，附更新器签名和 SHA-256 校验文件；
更新器签名并非 Windows Authenticode 签名。
旧测试版内部版本 `4.0.26-krill.N` 大于 `0.1.0`，需要手动安装一次；之后按新版本序列更新。

已完成本地静态检查和发布编译；此前本地试用已确认官方与 Krill 的 WS 标签正常显示。
本轮没有额外发送模型验收请求；已有后端测试的历史结果见早期版本说明，不作为本轮新测试结果。

## English

### Features

1. **Native WS in aggregation mode**: official accounts and Krill can use WebSocket through CCS for streaming output and tool calls.
2. **WS prewarming and incremental continuation**: forward the client's native connection prewarm and `previous_response_id` mechanisms.
3. **Native context compaction for Krill**: GPT compaction requests and encrypted results follow the native protocol instead of always becoming CCS text summaries.
4. **Compaction source protection**: track the source provider and account, reject known incompatible switches explicitly, preserve history and never silently delete compacted content.
5. **Automatic HTTP request compression**: eligible official/Krill requests use zstd with plain-JSON fallback on upstream refusal. This is separate from context compaction.
6. **HTTP fallback when WS is unavailable**: unsupported WS routes, protocol-conversion paths and handshake failures use the compatible HTTP path.
7. **Third-party authentication isolation**: Krill key failures are not presented as official-login failures that would trigger an official account refresh.
8. **Passive WS status chip**: show green/gray from actual normal traffic and update on HTTP fallback or observed interruption, without extra probes or token consumption.

### Other changes

- Show only WS using the original chip design without hover text; hide CMP while preserving context compaction.
- Fix WS evidence matching with hydrated candidate endpoints by normalizing configuration identity and JSON key order.
- Identify Krill by an exact, case-insensitive provider name, independent of API domain.
- Fresh installs include a blank Krill provider for users to enter their own endpoint and API key; existing configuration is preserved.
- About, update and recent-change links point to this repository's releases.

### Scope

The chip reflects recently observed provider transport, not every concurrent session. Gray can mean unverified or expired;
no traffic triggers no check, and evidence expires after 30 minutes. Compacted ciphertext is not guaranteed portable across
providers/accounts. Unknown imported history is tried intact; known source conflicts are rejected. Krill uses its configured
endpoint without automatic three-line rotation. Automatic failover routing retains its existing HTTP path. Normal conversation
and actual compaction retain upstream usage; passive status observation adds no tokens.

### Version and validation

This is a stable release, not a GitHub prerelease. The app, installer, updater and release all use **0.1.0**. Windows x64 setup EXE, updater signature and SHA-256
checksums are included. The updater signature is not Windows Authenticode.
Older test builds using internal `4.0.26-krill.N` versions require a one-time manual installation of 0.1.0.

Static checks and the release build were completed locally. Earlier local use confirmed official/Krill WS chips display
correctly. No new live model acceptance requests were sent for this release; historical backend tests are documented in
earlier releases and are not claimed as new results here.

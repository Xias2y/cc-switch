# CC Switch For Krill 0.1.1

## 中文

### 修复与改进

1. **取消压缩来源硬拦截**：来源记录仅用于诊断。手动切换供应商、官方账号或 Key 后，原生压缩历史会原样交给选中的上游尝试，不再由 CCS 提前返回 `compaction_provider_mismatch`，也不偷偷改选其他供应商。
2. **恢复其他密文状态的兼容修复**：携带原生压缩时，推理、工具加密片段和条目 ID 等仍可按上游真实错误进行原有的一次修复。修复期间原生压缩项完整保留；普通 `400/422` 不替换它，上游明确拒绝压缩本身时返回真实错误，不换成占位说明继续。
3. **WS 容量规则对齐**：上下游单帧上限为 64 MiB，整条消息上限跟随 CCS 原有 HTTP 请求体上限 200 MiB，允许多帧组成更大的消息；取消额外的“最多 8 个未完成响应”限制。超限使用关闭码 `1009`。
4. **保留 WS 握手错误详情**：对未成功升级的上游响应，最多读取 64 KiB、等待 5 秒，保留 JSON `error` 对象的原有字段。无有效错误对象时才使用供应商与 HTTP 状态说明。第三方 `401` 仍对客户端映射为 `502`，避免触发官方登录刷新；官方 `401` 保持原状态。5 秒仅用于失败后的错误体读取，不缩短正常握手等待。

### 使用范围

- “允许切换后尝试”不等于保证所有供应商或账号都能解密同一段历史。上游实际拒绝时保留压缩内容，便于切回来源继续。
- 原生压缩、HTTP zstd、WS 预热／续接、工具调用和被动 WS 标签继续保留。标签不新增探测或额外 token 请求；实际对话与本轮人工验收按上游规则计费。
- WS 容量采用 Superba 的“整条消息跟随 HTTP 上限、单帧单独限制”规则；CCS 的 HTTP 上限保持 200 MiB，不改成 Superba 的默认 256 MiB。
- 本版是稳定版，应用、安装包和更新器版本统一为 `0.1.1`。提供 Windows x64 EXE、更新器签名和 SHA-256 校验文件。

### 验证

后端整轮回归 4359 项通过；本机缺少创建符号链接的 Windows 权限，两项原有符号链接用例报 `1314`，已明确排除，未更改系统安全设置。供应商、代理与配置往返的集成回归 109 项通过；前端相关测试 26 项通过，另完成容量／错误边界、静态检查与发布编译。

实际 `gpt-6.1-sol` 验收中，官方与 Krill 的 WS 预热、增量续接、工具调用、原生压缩及重放、HTTP zstd 均通过。该轮官方生成的压缩交给 Krill 后保留了测试上下文；Krill 生成的压缩交给官方时收到上游密文拒绝，原错误和压缩内容均保留。这是本次样本结果，不保证其他账号、模型或压缩内容有相同兼容性。

不会将本机配置、账号凭据或原始测试记录上传到仓库。

## English

### Fixes and improvements

1. **Remove the compaction provenance admission gate**: provenance records are diagnostic only. After a manual provider/account/key switch, native compacted history reaches the selected upstream unchanged. CCS no longer rejects it locally with `compaction_provider_mismatch` or silently selects another provider.
2. **Restore compatible repairs of other encrypted state**: reasoning, encrypted tool-output parts and item ids can still use the existing single repair retry after a real upstream rejection. Native compaction items remain intact. Generic `400/422` errors do not rewrite them, and an explicitly rejected native compaction returns the original upstream error instead of continuing with a placeholder.
3. **Align WS capacity rules**: each leg accepts frames up to 64 MiB and complete messages up to CCS's existing 200 MiB HTTP body limit. Fragmented messages may exceed one frame. Remove the additional eight-unfinished-response admission limit. Oversized input closes with code `1009`.
4. **Preserve WS handshake errors**: read at most 64 KiB for up to five seconds after a rejected upgrade and retain the upstream JSON `error` object's fields. Only missing/invalid errors use a provider/status explanation. Third-party `401` remains mapped to client status `502` to avoid refreshing the official login; official `401` is unchanged. The five-second body-read bound does not shorten normal handshake waiting.

### Scope

- Allowing an attempt does not guarantee ciphertext portability across providers/accounts. On an upstream rejection the native compacted history remains available for returning to its source.
- Native compaction, HTTP zstd, WS prewarming/continuation, tool calls and passive WS status remain available. Status observation sends no additional probes or token requests; actual conversation and authorized live acceptance retain upstream usage.
- Message sizing follows Superba's HTTP-limit/frame-limit design, while preserving CCS's 200 MiB HTTP limit rather than adopting Superba's 256 MiB default.
- This is a stable release. The application, installer and updater all use `0.1.1`. Windows x64 setup EXE, updater signature and SHA-256 checksums are included.

### Validation

The full backend regression run passed 4,359 tests. Two original symlink tests encountered Windows privilege error `1314` and were explicitly excluded; system security settings were not changed. The provider/proxy/configuration integration suite passed 109 tests and the related frontend suite passed 26 tests. Capacity/error boundaries, static checks and the release build were also checked.

Live `gpt-6.1-sol` acceptance passed official/Krill WS prewarming, incremental continuation, tool calls, native compaction/replay and HTTP zstd. In this sample, official-origin compaction continued on Krill with its test context retained. Krill-origin compaction sent to the official upstream received an upstream ciphertext rejection; the original error and compacted content were preserved. Other accounts, models and ciphertexts may behave differently.

Local configuration, credentials and raw test records are not uploaded to the repository.
